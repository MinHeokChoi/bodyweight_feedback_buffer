## 1. 웜업 탭 UI 개편

### 배경

웜업 탭에 지금 네 덩어리가 있다 — 세션 변경 카드, 시작 버튼, 진행률 카드,
"오늘의 웜업" 항목 목록, 다시 웜업하기. 실제로 쓸 때 필요한 건 "지금 시작할까,
아니면 오늘 이미 했나" 둘뿐인데 목록이 화면 대부분을 차지한다.

### WR-1. "오늘의 웜업" 목록을 탭에서 뺀다

- 항목 목록은 웜업 시작(러너) 안에서 한 개씩 보인다. 탭에서 미리 볼 이유가 없다.
- 탭에 남는 것: 루틴 카드 · 시작 버튼 · 진행 상태 · 되돌리기.

**개별 체크 경로는 따로 만들지 않는다.**
항목 하나만 뒤늦게 고치는 전용 화면은 두지 않는다. 러너를 다시 돌면
(WR-4) 원하는 항목까지 넘겨서 고칠 수 있고, 그걸로 충분하다.

### WR-2. "세션 변경" → 루틴 이름을 보여준다

- 카드 제목을 고정 문구 대신 현재 루틴 이름(`WarmupSession.name`)으로 바꾼다.
- 부제 "항목 N개"는 유지한다. 목록이 사라진 만큼 루틴 크기를 알려주는 유일한 단서가 된다.
- **중복 방지:** 지금은 네비게이션 타이틀도 루틴 이름이다. 한 화면에 같은 이름이
  두 번 나오므로 타이틀은 "웜업"으로 고정한다.
- **용어 정리:** 코드는 `WarmupSession`("세션")이지만 타이머 탭에서 "세션"은
  운동 한 판을 뜻한다. 한 앱에 뜻이 다른 "세션"이 둘이면 헷갈린다.
  사용자에게 보이는 문구는 전부 **"루틴"**으로 통일한다. 모델 이름은 건드리지 않는다.

### WR-3. 건너뛰어도 끝까지 갔으면 완료

- 지금은 `isWarmupComplete = 모든 항목 체크`다. 러너에서 "건너뛰기"를 누르면
  항목이 체크되지 않으므로, 끝까지 돌아도 탭은 여전히 "오늘의 웜업 시작"을 보여준다.
- 바꾼다: **러너 마지막 항목까지 진행해 완료 화면에 도달하면 그날은 완료**다.
  건너뛴 항목이 몇 개든 상관없다.
- 완료 조건은 러너 도달 기준이다. 중간에 X로 닫으면 완료가 아니다.
- 저장 단위는 체크 상태와 같다 — **루틴별 · 날짜별**. 날짜가 바뀌면 초기화된다.
  다른 루틴으로 바꾸면 그 루틴은 아직 미완료다.

**진행률이 거짓말하지 않게 한다.**
9개 중 7개 체크하고 2개 건너뛴 날 "100%"라고 쓰면 틀린 말이다.
완료 상태에서는 퍼센트 대신 사실을 적는다 — `7개 완료 · 2개 건너뜀`.
막대는 완료 색으로 가득 채우되 숫자는 실제 체크 수를 따른다.

**완료 뒤 되돌리기.** "다시 웜업하기"는 남긴다. 체크뿐 아니라 완료 표시도 함께 푼다.

### WR-4. 완료한 뒤에도 다시 시작할 수 있다

하루에 두 번 웜업할 때가 있다. 지금은 완료하면 시작 버튼이 비활성이라 막힌다.

- 완료 후 버튼은 **살아있고**, 문구가 "웜업 다시 하기"로 바뀐다.
- 강조는 뺀다(`borderedProminent` → `bordered`). 오늘 할 일은 이미 끝났으므로
  화면에서 제일 센 요소일 이유가 없다. 완료 표시는 진행률 카드가 맡는다.
- 체크 상태는 유지한다. 다시 돌아도 이미 한 항목엔 "이미 완료"가 뜬다.
- 이 버튼이 WR-1에서 없앤 개별 수정 경로를 대신한다 — 건너뛴 항목까지 넘겨서
  마저 체크하면 된다.
- 루틴이 비어 있을 때만 비활성이다.

## 2. 타이머 탭 보강

### TR-1. 운동 시간 직접 추가 · 수정

타이머를 못 켠 날이 생긴다. 사후 입력이 필요하다.

**모델을 새로 만들지 않는다.** 수동 기록도 똑같은 `WorkoutSession`이다.
통계·기록·상세 화면이 전부 그대로 동작해야 한다. 이것이 이 요구사항의 핵심 제약이다.

- 입력 형태: **날짜 + (구간 종류, 분) 목록**. 그게 전부다.
  - 시작 시각은 묻지 않는다. "스트레칭 10분, 기술 연습 20분" 정도만 적으면 된다.
  - 구간은 순서대로 이어 붙인다. **수동 기록의 휴식은 0이다.**
    휴식은 타이머와 타이머 사이의 간격인데(D6), 사후 입력에는 그 간격이 없다.
    없는 값을 지어내지 않는다.
  - 통계는 날짜 단위로 묶이므로(D16) 시각이 없어도 정확하다.
- **기록 목록에서 수동 기록은 시각 자리에 "직접 입력"을 보여준다.**
  묻지 않은 시각을 지어내 시계처럼 표시하면 거짓말이 된다.
- 스트렝스의 랩/세트는 입력하지 않는다. 길이에서 파생된다(27분 → 3랩).
- **저장 전 검증** — 어기면 저장 불가, 무엇이 문제인지 문구로 알린다.
  - 길이가 0인 구간은 저장하지 않는다. 구간이 하나도 없으면 저장하지 않는다.
  - 미래 날짜는 받지 않는다.

#### 기존 기록 수정

같은 편집 화면을 쓴다. 타이머로 만든 기록도 고칠 수 있다(잘못 눌렀을 때).

**편집 화면은 시각을 다루지 않는다. 길이만 다룬다.**
이 기록의 목적은 구간별 누적 시간이고, 휴식은 그 부산물이지 기록 대상이 아니다.
그래서 "몇 시에 시작했나"를 고치게 하지 않는다.

- 구간 길이를 바꾸면 **그 뒤의 구간들이 통째로 밀린다.** 뒤 구간의 길이와
  구간 사이 간격(휴식)은 그대로 유지된다. 늘리는 데 한계를 두지 않는다.
- 세션 종료 시각은 마지막 구간을 따라 함께 움직인다.
- 구간 삭제, 구간 추가(맨 뒤에 붙임), 순서 변경을 허용한다.
- **길이를 바꾼 스트렝스 구간은 랩을 새 길이에서 다시 계산한다.**
  저장돼 있던 랩 배열은 옛 길이의 산물이라 그대로 두면 합이 안 맞는다.
  이때 "지금 바로 다음 운동으로"로 만들었던 짧은 랩은 사라지고 9분 기준으로 다시 나뉜다.
  **길이를 건드리지 않은 구간의 랩은 그대로 둔다.**
- **일시정지 기록은 사라진다.** 일시정지는 구간 길이에서 빠지므로, 남겨두면
  화면에 보이는 길이가 방금 입력한 길이와 달라진다. "20분"이라고 적었는데
  17분으로 보이는 셈이다. 손으로 총량을 고친 뒤에 붙들고 있을 이유가 없다.
  (구현하면서 드러났다. 처음에는 보존하기로 적었으나 위 모순 때문에 뒤집었다.)
- 진행 중인 세션은 편집하지 않는다. 끝난 기록만 대상이다.
- 출처를 남긴다: `WorkoutSession.source = .timer | .manual`.
  상세 화면에 표시하고, 통계는 구분 없이 합산한다.
  기존 JSON에 없는 필드이므로 **기본값 `.timer`로 디코딩**해 호환을 지킨다.
  타이머 기록을 수정해도 출처는 `.timer`로 남는다 — 시작은 타이머였던 게 사실이므로.
- 편집 이력은 남기지 않는다.

### TR-2. 운동 진행 중 피드백 추가

- "지금 피드백 적기"는 이미 **휴식 화면에만** 있다. 같은 버튼을 **구간 진행 중 화면**에도 둔다.
- 배치: 진행 중 화면은 이미 큰 숫자 · 세트 막대 · 버튼 두 개로 꽉 차 있다.
  하단에 버튼을 더 쌓지 말고 **툴바 아이콘**으로 넣는다. 누르는 실수도 줄어든다.
- **시트가 떠 있는 동안 경계 햅틱을 놓칠 수 있다.** `TimelineView`가 가려지면 갱신이
  멈추므로 세트/운동 경계 신호가 울리지 않는다. 시간 자체는 타임스탬프에서 다시
  계산하므로 손실이 없고, 시트를 닫으면 정확한 시각으로 복귀한다.
  → 신호를 놓치는 것은 허용한다(D8과 같은 판단). 대신 문서에 남긴다.
- **어떤 운동 중에 적었는지는 피드백에 붙이지 않는다.** 세션·구간과의 연결 없이
  기존 피드백과 똑같이 저장된다. 버튼은 입력 경로를 줄여줄 뿐이고, 그 이상의
  의미는 갖지 않는다.

## 3. 새 기능 — 시즌 측정 기록

### 배경

시즌 마지막 주차쯤에 1RM이나 기술 수행력을 "측정"한다. 지금은 이 결과가
어디에도 남지 않는다. "지난 시즌엔 이 정도 했구나"를 볼 수 있게 모아둔다.

이 기능의 존재 이유는 **시즌 간 비교**다. 비교가 성립하지 않으면 기록은 쓸모가 없다.
아래 설계는 전부 "비교가 깨지지 않게 하려면"에서 나왔다.

### MR-1. 구조 — 종목과 기록을 나눈다

**종목(측정 항목)** 은 한 번 정의하고 시즌마다 재사용한다.

| 필드 | 예시 | 비고 |
|---|---|---|
| 카테고리 | 물구나무 / 풀업 / 스트렝스 | 기존 목록에서 고르거나 새로 만든다 |
| 세부 동작 | 밸런스 / 최대 개수 / 벤치프레스 | 필수 |
| 제약 | "20~25분 동안 서 있는 시간만 세서 3분 채우기" | 자유 텍스트 |
| 단위 | 회 / kg / 초 / 분 | |
| 방향 | 높을수록 좋음 / 낮을수록 좋음 | MR-2 참고 |

**기록**은 측정할 때마다 쌓인다 — 종목 · 시즌 · 날짜 · 값 · 메모.

### MR-2. 값의 방향을 저장한다 (핵심)

측정 결과는 대부분 숫자 하나로 환원된다 — 풀업 12회, 1RM 60kg, 홀드 45초.
하지만 **방향이 반대인 종목이 있다.**

> 물구나무 밸런스: 3분을 **몇 번의 시도 안에** 채우는지 → **적을수록 잘한 것**

방향을 모르면 5회 → 3회 개선을 "↓ 감소"로 표시하게 된다. 시즌 비교가
이 기능의 전부인데 거기서 틀린 말을 하는 셈이다.
→ 종목마다 방향을 갖고, 변화 표시는 방향을 적용한 뒤 "개선 / 후퇴"로 쓴다.

### MR-3. 제약은 종목에 붙고, 기록에 복사된다

제약이 시즌마다 조용히 바뀌면 비교가 무의미해진다. 값은 같은데 조건이 달랐다는 걸
나중에 알 방법이 없다.

- 제약은 **종목 정의**에 적는다. 기록할 때마다 다시 쓰지 않는다.
- 기록에는 그 시점의 제약 문구를 **복사해 둔다**(`protocolSnapshot`).
- 종목의 제약을 나중에 고치면, 문구가 다른 과거 기록에는
  **"이때는 제약이 달랐어요"** 를 표시한다. 비교에서 빼지는 않되 숨기지도 않는다.

### MR-4. 시즌

- 시즌 = **이름 + 시작일**. 종료일은 두지 않는다 — 다음 시즌이 시작하면 이전 시즌이 끝난다.
  범위가 겹치거나 비는 상태를 만들 수 없어서 검증할 것이 없다.
- 항상 하나만 진행 중이다. 새 기록의 시즌 기본값은 진행 중인 시즌이다.
- 한 시즌에 같은 종목을 여러 번 측정할 수 있다.
  **시즌 대표값은 방향을 적용한 최고 기록**이고, 나머지는 종목 상세에서 전부 볼 수 있다.

### MR-5. 보기

- **종목 상세**: 시즌별 목록(최신 순) + 직전 시즌 대비 변화. 이게 주된 화면이다.
- **시즌 상세**: 그 시즌에 측정한 종목 전부를 한눈에.
- 시즌이 1년에 몇 번뿐이므로 차트보다 표가 읽기 좋다. 차트는 넣지 않는다.

### MR-6. 범위 제한

- 기존 `Skill`(기술 라이브러리)과 연결하지 않는다. 카테고리는 독립이다.
  "스트렝스"처럼 기술이 아닌 카테고리가 있고, 지금 묶어둘 이유가 없다.
  나중에 필요하면 선택 필드 하나를 더하면 되므로 미루는 비용이 싸다.
- 측정 중에 타이머를 돌리는 연동은 하지 않는다. 결과만 적는다.
- 목표값 설정, 알림, 사진/영상 첨부는 넣지 않는다.

### MR-7. 자리

**기술 라이브러리 탭의 툴바 왼쪽**에 진입점을 둔다.

- 지금 라이브러리 툴바는 오른쪽에 "기술 관리" 하나뿐이고 왼쪽이 비어 있다.
- 타이머 탭이 이미 같은 문법을 쓴다 — 왼쪽에 통계, 오른쪽에 기록.
  앱 안에서 "부가 목적지는 툴바"라는 규칙이 이미 서 있다.
- 5번째 탭은 만들지 않는다. 시즌당 몇 번 쓰는 화면에 탭을 내주면
  매일 쓰는 네 탭이 다 좁아진다.
- 아이콘은 `ruler`(측정).

### MR-8. 시즌 이름은 자동으로 짓는다

- 시작일에서 **연도 + 계절**로 만든다. 예: "2026 가을".
- 계절 경계: 봄 3~5월 · 여름 6~8월 · 가을 9~11월 · 겨울 12~2월.
- 겨울은 해를 걸치므로 **시작 연도**를 쓴다. 2026년 12월 ~ 2027년 2월 → "2026 겨울".
- 같은 이름이 이미 있으면 뒤에 번호를 붙인다 — "2026 가을 (2)".
- 이것은 **기본값일 뿐이고 언제든 고칠 수 있다.**

### MR-9. 단위

회 · kg · 초 · 분. 넷으로 고정한다.
초는 1분이 넘어가면 `mm:ss`로 보여준다.

## 4. 결정 기록

| # | 결정 | 근거 |
|---|---|---|
| N1 | 웜업 탭에서 항목 목록을 없앤다 | 러너에서 보이므로 미리 볼 이유가 없다 |
| N2 | 개별 체크 전용 경로는 만들지 않는다 | "웜업 다시 하기"(N4)가 대신한다 |
| N3 | 루틴 이름을 카드에 두고 타이틀은 "웜업"으로 고정 | 한 화면에 같은 이름이 두 번 나오지 않게 |
| N4 | 완료 후에도 다시 시작할 수 있다. 버튼 강조는 뺀다 | 하루 두 번 하는 날이 있다 |
| N5 | 러너를 끝까지 돌면 건너뛴 항목이 있어도 완료 | 건너뛰기는 포기가 아니라 선택이다 |
| N6 | 완료 상태에서 진행률 퍼센트 대신 "N개 완료 · M개 건너뜀" | 100%가 아닌데 100%라고 쓰지 않는다 |
| N7 | 화면 문구의 "세션"을 "루틴"으로 통일 | 타이머의 "세션"과 뜻이 충돌한다 |
| N8 | 수동 입력은 날짜 + 구간별 분만 받는다 | 사후 입력의 목적은 빠름이다 |
| N9 | 수동 기록의 휴식은 0 | 사후 입력에 간격이라는 사실이 없다 |
| N10 | 수동 기록은 시각 대신 "직접 입력" 표시 | 묻지 않은 값을 지어내지 않는다 |
| N11 | 편집은 길이만 다루고, 늘리면 뒤 구간이 밀린다 | 기록의 목적은 구간별 누적 시간이다. 휴식은 부산물 |
| N11b | 편집하면 일시정지 기록은 사라진다 | 남겨두면 보이는 길이가 입력한 길이와 달라진다 |
| N12 | 길이를 바꾼 스트렝스 구간은 랩을 다시 계산 | 옛 길이의 랩을 그대로 두면 합이 안 맞는다 |
| N13 | 피드백에 운동 맥락을 붙이지 않는다 | 필요 없다고 판단 |
| N14 | 측정 종목마다 값의 방향(높을수록/낮을수록 좋음)을 저장 | 방향이 반대인 종목이 있다 |
| N15 | 제약은 종목에 두고 기록에 복사 | 조건이 바뀐 걸 모르면 비교가 거짓이 된다 |
| N16 | 시즌은 이름 + 시작일. 종료일 없음 | 겹치거나 비는 구간을 만들 수 없다 |
| N17 | 한 시즌에 여러 번 측정 시 방향 적용 최고값이 대표 | 마지막 값이 최고라는 보장이 없다 |
| N18 | 측정을 기술 라이브러리와 연결하지 않는다 | 기술이 아닌 카테고리가 있다. 미루는 비용이 싸다 |
| N19 | 측정 진입점은 기술 라이브러리 툴바 왼쪽 | 타이머 탭과 같은 문법. 탭은 늘리지 않는다 |
| N20 | 시즌 이름은 "연도 + 계절"로 자동 생성, 수정 가능 | 매번 짓는 수고를 없애되 강제하지 않는다 |
| N21 | 단위는 회 / kg / 초 / 분 넷으로 고정 | |
