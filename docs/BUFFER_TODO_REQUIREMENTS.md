# 피드백 버퍼 — 점수제에서 todo로

작성일: 2026-09-16 (갱신: 2026-09-17)
상태: **구현 완료**

---

## 1. 배경

지금 버퍼는 우선순위 점수로 정렬한다.

```
점수 = 중요도×10 + 연습횟수×8 + 경과일×0.7 + 미검토일×1.2
```

중요도는 최대 50점인데 날짜는 **하루에 1.9점씩** 쌓인다. 그래서 한 달만 지나면
나이가 중요도를 이긴다. 실제로 확인한 값이다.

| 피드백 | 점수 |
|---|---|
| 방금 적은 것, 중요도 ★5 | 50 |
| 30일 된 것, 중요도 ★1 | 67 |
| 120일 된 것, 중요도 ★1 | 238 |

**방금 적은 피드백은 구조상 항상 맨 아래에 깔린다.** 스크롤하지 않으면 보이지 않아서,
"새 기술에 피드백을 적었는데 버퍼에 안 보인다"고 느끼게 된다.

점수는 또한 **설명이 필요한 숫자**다. 카드마다 "238점 ⓘ"이 붙어 있고 그것이 무슨 뜻인지
알려주는 팝오버가 따로 있다. 내가 정한 것이 아니라 앱이 정한 순서라서 그렇다.

## 2. 방향 — 내가 정한다

Amazing Marvin의 방식을 가져온다. 알고리즘이 순서를 정하지 않는다.
**사용자의 행동이 순서다.**

- 새로 적으면 맨 위
- "또 하기"를 누르면 맨 위
- "해결"을 누르면 목록에서 사라진다

목록은 **지금 붙잡고 있는 것들**이 되고, 손대지 않은 것은 아래로 내려간다.

## 3. 순서는 배열 그 자체로 둔다

손으로 끌어 순서를 바꾸기로 했으므로(Q3), 계산으로 순서를 만들 수 없다.
그렇다고 순서 번호 필드를 새로 둘 필요도 없다.

**저장된 `feedbacks` 배열의 순서가 곧 화면의 순서다.**

- 새로 적으면 배열 맨 앞에 넣는다
- 손으로 끌면 배열을 그대로 옮긴다 (기술 목록에서 이미 쓰는 `moveItems`와 같다)
- 정렬 함수가 사라진다. 지금 매번 점수를 다시 계산해 정렬하던 것이 없어진다
- 범주 필터나 기술별 목록은 이 배열을 걸러내기만 하므로 순서가 유지된다

### 한 번의 이관이 필요하다

지금 배열은 **추가된 순서**, 즉 오래된 것이 앞이다. 그대로 쓰면 목록이 거꾸로 선다.
처음 한 번 `referenceDate`(마지막으로 손댄 시각) 내림차순으로 정렬해 둔다.

이미 `feedbackSchemaVersion`(현재 1)이 있으므로 2로 올리면서 한 번만 돌린다.

## 4. 잃는 것 — 이게 진짜 비용이다

점수제는 **방치된 것을 끌어올리는 장치**였다. 오래 안 본 피드백일수록 위로 왔다.
recency 정렬은 정확히 그 반대다. **한 번 밀린 것은 영영 바닥에 남는다.**

버리면 안 되는 질문이 남는다 — *내가 무엇을 피하고 있는가?*

세 가지 중 하나를 골라야 한다.

| | 방식 | 평가 |
|---|---|---|
| A | 그냥 받아들인다 | 가장 단순하다. 다만 오래된 것은 존재를 잊게 된다 |
| B | **순서는 건드리지 않고 표시만 한다** — "45일째" 같은 조용한 라벨 | 추천. 순서의 주도권은 사용자에게 두되 사실은 알려준다 |
| C | "오래 묵은 것" 필터나 섹션을 따로 둔다 | 화면이 늘어난다. B로 부족하면 그때 |

**B를 추천한다.** 카드에 이미 "120일 경과"가 있으므로 새로 만들 것도 없다.
오래된 것만 색을 죽이거나 눈에 띄게 하면 된다.

## 5. 오늘 할 것

Marvin의 핵심이자 Q1을 푸는 열쇠다.

- 버퍼 탭 **위쪽에 "오늘 할 것" 구역**을 둔다. 탭은 늘리지 않는다
  (측정 기능 때와 같은 판단 — 매일 쓰는 네 탭을 좁히지 않는다)
- 아래는 전체 목록. 거기서 오늘 할 것을 골라 올린다
- **날이 바뀌면 자동으로 비워진다.** 어제 못 한 것을 치우는 일이 없다
- 오늘 목록이 비어 있으면 구역 자체를 숨긴다. 안 쓰면 없는 기능이 된다
- **담기: 전체 목록의 카드를 왼쪽으로 스와이프 → "오늘"**
- **빼기: 오늘 목록의 카드를 왼쪽으로 스와이프 → "빼기"**
- 오늘 목록에서 "또 하기"나 "해결"을 누르면 **조용히 사라진다.** 몇 개 했는지 세지 않고,
  완료 표시나 축하 문구도 없다. 다 비면 구역이 숨는다

### 구현 메모 — 목록을 `List`로 바꿔야 한다

지금 버퍼는 `ScrollView` + `LazyVStack`이다. 스와이프(`swipeActions`)와
손으로 끌기(`onMove`)는 둘 다 `List` 안에서만 기본으로 동작한다.
`List`로 바꾸면 두 기능을 직접 만들지 않아도 된다. 카드 모양은 행 배경과 여백을
걷어내서 지금과 같게 맞춘다.

### Q1이 여기서 풀린다

"또 하기"를 누르면 **전체 목록에서는 맨 위로 가고, 오늘 목록에서는 빠진다.**

세션 중에 A를 하고 또 하기를 눌렀을 때 A가 계속 눈앞에 있는 문제는,
오늘 목록에서 빠지는 것으로 해결된다. 전체 목록의 순서는 "최근에 손댄 것"이라는
뜻을 유지하면 된다. 오늘 할 일은 오늘 목록을 보면 되니까.

## 6. 카드에서 덜어내는 것

- **"238점 ⓘ"** 와 점수 설명 팝오버
- 카드 왼쪽의 **점수 등급 색 막대** (매우 높음/높음/보통/낮음)
- `FeedbackScoring`의 점수 계산 자체 (등급 색·임계값 포함)
- 메타 줄에서 **연습 횟수**와 **단계 칩**(새 피드백 / 연습 중 / 적응 중).
  카드에는 **중요도만** 남긴다
- 연습 횟수는 데이터로는 계속 쌓는다. 피드백 수정 화면의 "기록" 칸에서 볼 수 있다

### 경과일은 조건부로 남긴다

카드를 중요도만 남기고 비우면 4장에서 고른 B안(방치 표시)이 함께 사라진다.
그래서 **오래된 것에만** 경과일을 보여준다 — 30일이 넘으면 "45일째"가 조용히 붙고,
그 아래는 아무것도 붙지 않는다. 평소에는 깨끗하고, 묵은 것만 스스로 드러난다.

## 7. 그대로 두는 것

- **해결 / 또 하기 / 수정 / 삭제** 네 버튼. 이름만 "연습했어요" → "또 하기"로
- **체력 훈련 / 기술 훈련 필터**
- **보관함**과 해결 동작

## 7-1. 기술별로 보기

- 필터 막대를 가로로 스크롤되는 칩으로 바꾸고, 범주(체력/기술) 칩 뒤에 기술 칩을 잇는다
- 기술 칩은 **피드백이 하나라도 있는 기술만** 보여준다. 빈 기술까지 늘어놓으면 찾기 어렵다
- **필터가 걸려 있는 동안에도 끌 수 있다. 다만 저장하지 않는다.**
  운동하면서 "이번엔 이 순서로 보자"고 잠깐 늘어놓는 용도다.
  - 걸러낸 목록의 순서는 화면에만 있는 임시 순서다
  - 필터를 풀거나 다른 필터로 바꾸면 임시 순서는 버려지고 저장된 순서로 돌아온다
  - 다른 탭(타이머)에 다녀와도 유지된다. 운동 중에 탭을 오가도 흐트러지지 않게
  - 앱을 완전히 끄면 사라진다
  - 임시 순서 중에 "또 하기"를 눌러도 **화면에서는 제자리**에 둔다.
    저장된 목록에서는 맨 위로 가지만, 운동 중에 늘어놓은 것이 튀면 안 된다
  - 해결·삭제한 항목은 임시 순서에서도 빠지고, 새로 적은 것은 맨 위에 붙는다
  - 임시 순서가 적용된 동안 목록 위에 "필터 중 순서는 저장되지 않아요 · 원래대로"를 작게 띄운다.
    처음 한 번만 알리는 대신 계속 보이게 했다 — 임시라는 걸 잊고 저장된 줄 착각하지 않게
- 기술 라이브러리의 기술별 피드백 목록도 같은 순서를 따른다

| B2 | 배열 순서가 곧 화면 순서 | 순서 필드를 새로 두지 않는다. 기술 목록이 이미 같은 방식이다 |

| B11 | 기술별 필터 추가, 피드백 있는 기술만 칩으로 | 핸드스탠드만 따로 보고 싶다 |
| B12 | 필터 중 드래그는 임시 — 필터를 풀면 저장된 순서로 돌아온다 | 운동 중 참고용으로 늘어놓되, 걸러낸 목록의 이동을 전체 순서에 억지로 반영하지 않는다 |
| B13 | 오늘 할 것에 담기·빼기는 왼쪽 스와이프 | 카드에 버튼이 이미 넷이다 |
| B14 | 오늘 목록에서 끝낸 것은 조용히 사라진다 | 세는 숫자가 또 하나의 점수가 되지 않게 |
